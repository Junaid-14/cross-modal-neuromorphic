## Group 1 — Era-1 notebook monoliths (copy-paste clones)

Line-number forensics show two lineages: `m7_trimodal_cl.py` and `m7_smoke_test.py` share **identical class line numbers** (560/638/720/814/…/1815) → `m7_smoke_test.py` is a truncated copy of `m7_trimodal_cl.py`. `m7_raw.py` → `m7_mps.py` is the second lineage (machine translation via `convert_mps.py`). `m7_nmnist_smoke_test.py` is a separate hand-written descendant of the MPS branch.

### `code/m7_raw.py` (3877) — DELETE

**Why dead:** raw Kaggle/Jupyter export (keeps `# %% CELL N` markers). Re-defines the 7 core classes plus the whole legacy bi-modal model zoo (`Model_1..5_SHD` L1068-1158, `Model_1..5` baselines L1158-1275) and ablations (`EWC` L2502, `M7_NoSCL/M7_FixedGate/M7_SharedHead` L2893-2921). Superseded by `m7_trimodal_run_provenance.py`.

**HIGH — `DEAD-002` — not valid Python.** Lines **2-4** and **17-23** are uncommented shell-magic (`!pip install …`). As a `.py` file this is a `SyntaxError`: CPython cannot parse/import/run it. This is what makes it a *raw* notebook dump, and it is **unique** to this file — the converted sibling `m7_mps.py` has these exact lines commented (`# !pip …`).

**MEDIUM — `DEAD-001` — dead monolith.** Delete, or archive together with `m7_mps.py`. Internal numerical/logic behaviour is a clone of the provenance module and is not separately catalogued.

### `code/m7_mps.py` (3900) — DELETE

**Why dead:** MPS port of `m7_raw.py` generated by `convert_mps.py`; same 7 classes + zoo (L633-2944). Superseded by the provenance module (which already auto-selects MPS→CUDA→CPU). Runs a training smoke-test at module scope (L560-576) after loading datasets → **importing it trains**.

**MEDIUM — `DEAD-004` — drift from its generator (unique).** It is supposed to be a pure machine translation of `m7_raw.py`, but the two disagree: `!pip` lines are **commented** here (L2-4/L17-23) and **uncommented** in `m7_raw.py`, and `convert_mps.py` never edits pip lines. So the current `m7_mps.py` **could not have been produced by running `convert_mps.py` on the current `m7_raw.py`** — it is an orphaned snapshot, not a rebuildable artifact. Regeneration is also unsafe (see `DEAD-011`). Delete both files together; do not try to reconcile.

**HIGH — `DEAD-003` — dead clone, trains on import.** Delete (regenerable). Never import.

> Clone note: the redundant double `torch.manual_seed(42)` at L560-561 and any internal logic bugs mirror `m7_raw.py`/the live code — not filed.

### `code/m7_trimodal_cl.py` (3759) — DELETE / archive

**Why dead:** full Era-1 tri-modal CL notebook dump; 7 classes + zoo + ablations (L560-2871). Superseded by the provenance module. **Executes the entire experiment at import** (module scope to L3756): dataset load, CL loop, energy analysis, and file writes.

**MEDIUM — `DEAD-006` — manufactures paper artifacts from an analytical estimate (unique, RULE 1).** On import it computes an **analytical SynOps** energy estimate, renders it as per-inference pJ and a figure titled "… × more efficient" (`fig_energy.pdf`), and writes **`paper_tables.tex`** (L3465-3577) and `energy_results.json` (L3329-3361). These are simulator/analytical numbers, not measured hardware energy — exactly what contested-facts #6 and RULE 1 forbid quoting. Retirement should kill this number-manufacturing path, not just the file, so nobody re-runs it and lifts the LaTeX/energy output into the paper.

**HIGH — `DEAD-005` — dead full-run on import.** Delete or archive; never import.

### `code/m7_smoke_test.py` (2070) — DELETE

**Why dead:** a **truncated copy of `m7_trimodal_cl.py`** — identical class line numbers (560/638/720/814/956/…/1815), cut off after `ContinualLearner` (no EWC/ablation/energy). Runs an N-MNIST/SHD/DVS smoke-train at module scope (L2003-2021) after dataset load → importing it trains. Superseded by the provenance module.

**HIGH — `DEAD-007` — dead clone, trains on import.** No unique bug beyond being a redundant subset clone; delete. Use `pytest tests/` for fast validation.

### `code/m7_nmnist_smoke_test.py` (472) — DELETE

**Why dead:** hand-written (not a notebook dump) single-file N-MNIST smoke test; re-defines the core classes (L121-318, audio backbone skipped at L228-229). Superseded by the provenance module.

Two secondary issues noted inside DEAD-008 but **not filed separately** (low value on a dead file, and partly systemic/clone): the `QUICK_SUBSET` `torch.randperm` at L100 runs **before** `torch.manual_seed(42)` at L419 → the subset is non-deterministic; and results are printed (L443-445) without spike-rate/sparsity, i.e. accuracy-travels-alone — the same systemic reporting gap present elsewhere in the codebase.

## Group 2 — dead one-off tooling

### `code/convert_mps.py` (182) — DELETE

**Why dead:** one-off codegen that string-transforms `m7_raw.py` → `m7_mps.py`; both ends are retired monoliths and the provenance module already handles MPS. `DEAD-009` (medium).

**HIGH — `DEAD-010` — overwrites `code/m7_mps.py` on import (unique, safety).** No `__main__` guard: it reads `m7_raw.py` (L7-8) and **unconditionally writes/overwrites `code/m7_mps.py`** (L173-174) at module scope — no backup, no diff, no confirmation. Any `import convert_mps` silently regenerates the file, and since current `m7_raw.py` has uncommented `!pip` lines the regenerated output would differ from the current `m7_mps.py`. Violates the repo's "show a diff before overwriting" rule.

**MEDIUM — `DEAD-011` — brittle exact-string replace silently no-ops (unique, correctness).** The transforms are literal `.replace()`/regex edits with **no check that any substitution matched**. Two are already stale vs current `m7_raw.py`:
- `EmbeddingReplayBuffer`: target expects `device=None` (L91-93), but `m7_raw.py` L1774-1776 has `device: str = 'cuda'`; the regex at L70-84 only matches bare `device='cuda'`, not the annotated form → neither fires, auto-detect never inserted.
- `ContinualLearner`: target expects `… device=None, lr=1e-3, weight_decay=1e-4, gradient_clip=1.0` (L102-103), but `m7_raw.py` L1883-1884 is `… device='cuda', replay_batch=32, replay_weight=0.3`.

A regenerated `m7_mps.py` would therefore silently keep a **CUDA default and break on MPS/CPU**, with no error — the concrete reason regeneration (DEAD-004) is unsafe.

### `code/modify_notebook.py` (569) — ARCHIVE

**Why dead & broken:** patches `NeurIPS2026_M7_clean (3) (1).ipynb`, which **no longer exists** (removed in git `837d7f9`; no `.ipynb` anywhere in the tree). Per CLAUDE.md this file is now the **only surviving record of the old notebook's cell structure**, so archive rather than hard-delete.

**HIGH — `DEAD-012` — crashes immediately.** `open(… .ipynb)` at L8-9 raises `FileNotFoundError` on every run today.

**HIGH — `DEAD-013` — destructive in-place overwrite on import (unique, safety).** No `__main__` guard; reads the notebook (L8-9) and `json.dump`s back to the **same path** (L563-564) with no backup. Were the target present, importing the module would destructively rewrite it.

**MEDIUM — `DEAD-014` — `list(str)` char-split bug (unique, correctness).** `src_text` is a **string** (`''.join(src)` at L207). L558 stores `cells[…]['source'] = list(src_text)`, splitting it into a list of **single characters** instead of lines → a malformed `source` field for nbformat. Unreachable today (crashes at L9 first) but a real defect. Fix would be `splitlines(keepends=True)` — moot if archived.

### `code/monitor_and_stop.py` (61) — DELETE

**Why dead:** throwaway log-watcher from an Era-1 run; foreign log path `/Users/agent1/…/train.log` (L9) and a fixed PID with no meaning here; no `train.log` exists. `DEAD-015` (medium). (This is the only file in the set with a `__main__` guard, L60-61.)

**HIGH — `DEAD-016` — hardcoded-PID kill can hit an unrelated process (unique, safety).** `PID = 16672` (L12). In an infinite `while True` loop (L33) watching the foreign log (which never exists here → parses nothing → loops forever), and if the plateau condition were met it runs `kill -15 16672` (L44) then `kill -9 16672` (L48). PID 16672 on any machine is whatever process currently holds that id — signalling a hardcoded literal PID can terminate the **wrong** process.

### `code/benchmark_mps_real.py` (54) — DELETE

**Why dead:** one-off throughput benchmark that imports the **legacy bi-modal package** (`Models.registry.build_model` L9, `Dataloaders.nmnist_loader.get_nmnist_loaders` L11) — not M7 — and runs at module scope (L19-54, no guard). Out of scope of the maintained code. `DEAD-017` (medium). (`Models/registry.py` and `Dataloaders/nmnist_loader.py` do exist at repo root, but are the out-of-scope legacy package.)

**HIGH — `DEAD-018` — foreign machine path + MPS-only device (unique, dependencies).** L6 `sys.path.insert(0, /Users/agent1/Documents/neuromorphic/m7-trimodal-cl)` is another developer's absolute path that does not exist here; the legacy imports depend on it and will `ModuleNotFoundError`. L15 hardcodes `torch.device('mps')` with no CUDA/CPU fallback → also crashes on any non-Apple-Silicon host. The file cannot run anywhere as written.
